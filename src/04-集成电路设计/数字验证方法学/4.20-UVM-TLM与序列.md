## 1. 事务级建模（TLM）

### 1.1 TLM概述

TLM（Transaction-Level Modeling）是UVM中组件间通信的基础机制。与传统的信号级通信不同，TLM在**事务级别**传递数据，提高了仿真效率和代码抽象层次。

### 1.2 TLM端口类型

UVM定义了三种主要的TLM端口类型：

| 端口类型 | 方向 | 说明 | 使用场景 |
|----------|------|------|----------|
| `uvm_port` | 输出 | 发起调用 | Driver发送请求 |
| `uvm_export` | 输入 | 接收调用 | Sequencer接收请求 |
| `uvm_analysis_port` | 输出（广播） | 一对多广播 | Monitor广播事务 |

**TLM通信接口**：

```systemverilog
// 请求-应答接口（seq_item_port/export）
uvm_seq_item_port   #(REQ, RSP)  // 发起方（Driver）
uvm_seq_item_export #(REQ, RSP)  // 接收方（Sequencer）

// 分析端口（广播接口）
uvm_analysis_port   #(T)         // 发送方（Monitor）
uvm_analysis_imp    #(T)         // 接收方（Scoreboard）
uvm_analysis_export #(T)         // 中间转发
```

### 1.3 uvm_tlm_fifo

`uvm_tlm_fifo` 是UVM内置的事务级FIFO，用于组件间的异步数据传输：

```systemverilog
// FIFO声明与使用
uvm_tlm_fifo #(axi_transaction) tx_fifo;

function void build_phase(uvm_phase phase);
    tx_fifo = new("tx_fifo", this, 16);  // 深度16
endfunction

// 写入
task write_to_fifo();
    axi_transaction txn;
    txn = new();
    txn.awaddr = 32'h1000;
    tx_fifo.put(txn);  // 阻塞写入
endtask

// 读取
task read_from_fifo();
    axi_transaction txn;
    tx_fifo.get(txn);  // 阻塞读取
    `uvm_info("FIFO", $sformatf("Got: %s", txn.convert2string()), UVM_MEDIUM)
endtask
```

**FIFO类型对比**：

| FIFO类型 | 容量 | 特点 | 适用场景 |
|----------|------|------|----------|
| `uvm_tlm_fifo` | 可配置 | 通用FIFO | 组件间缓冲 |
| `uvm_tlm_analysis_fifo` | 可配置 | 非阻塞写入 | Monitor数据缓存 |
| `uvm_analysis_port` | 无缓冲 | 广播到多个接收端 | 一对多分发 |

### 1.4 组件间连接方式

```systemverilog
// 在env的connect_phase中建立连接
function void my_env::connect_phase(uvm_phase phase);
    // Driver ↔ Sequencer 连接
    axi_agent.sequencer.seq_item_port.connect(axi_agent.driver.seq_item_export);
    
    // Monitor → Scoreboard 连接（分析端口广播）
    axi_agent.monitor.ap.connect(scoreboard.from_axi);
    
    // Monitor → Coverage 连接
    axi_agent.monitor.ap.connect(coverage_collector.analysis_export);
endfunction
```

## 2. 序列与激励生成

### 2.1 uvm_sequence_item（事务定义）

`uvm_sequence_item` 定义了一个事务的数据内容，是激励生成的基本单元：

```systemverilog
class mem_transaction extends uvm_sequence_item;
    `uvm_object_utils(mem_transaction)
    
    // 事务字段
    rand bit [31:0] addr;
    rand bit [31:0] data;
    rand bit        is_write;
    rand bit [1:0]  burst_type;
    
    // 地址空间约束
    constraint valid_addr {
        addr inside {[32'h0000_0000:32'h0000_FFFF]};  // 64KB地址空间
        addr[1:0] == 0;  // 字对齐
    }
    
    // 读写比例约束
    constraint rw_ratio {
        is_write dist { 1 := 60, 0 := 40 };  // 60%写，40%读
    }
    
    // Burst类型约束
    constraint burst_valid {
        burst_type inside {[0:2]};  // FIXED, INCR, WRAP
    }
    
    function new(string name = "mem_transaction");
        super.new(name);
    endfunction
endclass
```

### 2.2 uvm_sequence（序列组织）

`uvm_sequence` 将多个 `sequence_item` 组织成有意义的操作序列：

```systemverilog
// 简单序列：连续写入
class burst_write_sequence extends uvm_sequence #(mem_transaction);
    `uvm_object_utils(burst_write_sequence)
    
    rand int unsigned burst_len;
    rand bit [31:0]   base_addr;
    
    constraint valid_burst {
        burst_len inside {[1:16]};
        base_addr inside {[0:32'hFFFF]};
        base_addr[1:0] == 0;
    }
    
    function new(string name = "burst_write_sequence");
        super.new(name);
    endfunction
    
    task body();
        `uvm_info("SEQ", $sformatf("Starting burst write, len=%0d, addr=0x%08h", 
                 burst_len, base_addr), UVM_MEDIUM)
        
        for (int i = 0; i < burst_len; i++) begin
            mem_transaction txn;
            txn = mem_transaction::type_id::create("txn");
            
            start_item(txn);
            assert(txn.randomize() with {
                addr     == base_addr + i * 4;
                is_write == 1;
                data     == i * 0x1111_1111;
            });
            finish_item(txn);
        end
        
        `uvm_info("SEQ", "Burst write completed", UVM_MEDIUM)
    endtask
endclass
```

### 2.4 约束随机激励（Constraint Random）

约束随机测试（Constraint Random Testing, CRT）是UVM的核心优势之一：

```systemverilog
class smart_sequence extends uvm_sequence #(mem_transaction);
    `uvm_object_utils(smart_sequence)
    
    // 场景化约束
    typedef enum {NORMAL, STRESS, BOUNDARY} test_scenario_e;
    rand test_scenario_e scenario;
    
    constraint scenario_dist {
        scenario dist {
            NORMAL   := 50,
            STRESS   := 30,
            BOUNDARY := 20
        };
    }
    
    task body();
        repeat(1000) begin
            mem_transaction txn;
            txn = mem_transaction::type_id::create("txn");
            start_item(txn);
            
            // 根据场景施加不同约束
            case(scenario)
                NORMAL: begin
                    assert(txn.randomize() with {
                        addr inside {[32'h100:32'hF000]};
                    });
                end
                STRESS: begin
                    assert(txn.randomize() with {
                        // 连续访问同一cache line
                        addr[11:0] inside {[0:63]};
                    });
                end
                BOUNDARY: begin
                    assert(txn.randomize() with {
                        addr inside {0, 4, 32'hFFFC, 32'hFFFF};
                    });
                end
            endcase
            
            finish_item(txn);
        end
    endtask
endclass
```

**约束求解的数学基础**：

约束随机激励的生成本质上是约束满足问题（CSP）的求解过程：

$$S = \{x \in D \mid C_1(x) \wedge C_2(x) \wedge \cdots \wedge C_n(x)\}$$

其中：
- $x$：随机变量向量
- $D$：变量的定义域
- $C_i(x)$：第 $i$ 个约束条件
- $S$：可行解空间

求解器在可行解空间 $S$ 中按指定分布进行采样。当使用 `dist` 约束时：

$$P(x = v_i) = \frac{w_i}{\sum_{j} w_j}$$

其中 $w_i$ 为值 $v_i$ 的权重。

### 2.5 序列仲裁（uvm_sequencer_arbiter）

当多个序列同时运行时，sequencer需要仲裁器决定执行顺序：

| 仲裁模式 | 说明 | 适用场景 |
|----------|------|----------|
| `SEQ_ARB_FIFO` | 先来先服务（默认） | 一般场景 |
| `SEQ_ARB_STRICT` | 严格优先级 | 紧急事务优先 |
| `SEQ_ARB_WEIGHTED` | 加权轮询 | 公平调度 |
| `SEQ_ARB_RANDOM` | 随机选择 | 压力测试 |
| `SEQ_ARB_USER` | 用户自定义 | 特殊需求 |

```systemverilog
// 设置仲裁模式
function void my_sequencer::build_phase(uvm_phase phase);
    super.build_phase(phase);
    set_arbitration(SEQ_ARB_WEIGHTED);
endfunction

// 序列优先级设置
class high_priority_seq extends uvm_sequence #(mem_transaction);
    task body();
        this.set_priority(100);  // 高优先级
        // ...
    endtask
endclass
```
