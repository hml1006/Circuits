# 3.16 虚拟内存与存储管理

> **本章定位**：补上 CPU 微架构与操作系统之间的关键一层——虚拟地址如何变成物理地址、缓存如何与页表协作，以及 TLB/缺页对性能的影响。

> **前置知识**：[3.14 存储层次与缓存一致性](3.14-存储层次与缓存一致性.md)（Cache、TLB 基础）；[3.15 现代CPU实现分析](3.15-现代CPU实现分析.md)（乱序、访存流水线）。

## 1. 为什么需要虚拟内存

如果程序直接使用物理地址，会面临四个问题：

1. **隔离**：一个进程不能读写另一个进程的内存；
2. **重定位**：程序加载到任意物理地址都能运行；
3. **容量**：程序可以大于物理内存，靠换页扩展；
4. **共享**：多个进程共享同一份只读代码或文件映射。

虚拟内存给每个进程一个独立的**虚拟地址空间**，由 MMU（内存管理单元）在每次访存时翻译成物理地址。程序看到的是连续地址，物理页可以分散在不连续的物理内存中。

## 2. 地址转换：页表与 TLB

### 2.1 页与页表

虚拟地址和物理地址都按**页**（page）划分，常见页大小为 4 KiB。虚拟地址分为：

```
| 虚拟页号 VPN | 页内偏移 offset |
```

页表项（PTE）保存物理页号 PPN 与权限位（读/写/执行、用户/内核、脏、访问、有效）。地址转换：

$$
\text{物理地址}=\text{PPN}\times\text{页大小}+\text{offset}
$$

### 2.2 TLB

页表在主存中，每次访存都查页表会让性能减半。**TLB**（Translation Lookaside Buffer）是页表项的高速缓存：

- 命中：一个周期内完成 VPN → PPN 转换；
- 未命中：硬件页表遍历（page walk）或软件异常处理。

现代 CPU 通常有 L1 dTLB、L1 iTLB 与二级 TLB；TLB 容量有限，频繁切换进程或大工作集会降低命中率。

### 2.3 一个例子

假设 32 位虚拟地址、4 KiB 页、两级页表，每级页表 1024 项：

- 页内偏移 12 位；
- 一级页号 10 位，二级页号 10 位；
- 一级页表 4 KiB，二级页表 4 KiB。

访问一个地址最多需要 2 次页表访存 + 1 次数据访存；TLB 命中则只需 1 次数据访存。这就是 TLB 对性能影响巨大的原因。

## 3. 多级页表与页大小

### 3.1 多级页表

单级页表在 64 位地址空间下会大到无法接受。多级页表只保留实际用到的子树，节省内存。代价是页表遍历次数增加，因此现代 CPU 用**页表缓存**（page walk cache）和更大的 TLB 来补偿。

### 3.2 大页

大页（2 MiB、1 GiB）减少页表层级与 TLB 项数，提高 TLB 覆盖率，常用于数据库、虚拟化和大内存应用。代价是内部碎片与换页粒度变大。

### 3.3 页表项格式

典型 PTE 包含：

| 字段 | 作用 |
|---|---|
| PPN | 物理页号 |
| V | 有效 |
| R/W/X | 读/写/执行权限 |
| U/S | 用户/内核 |
| A | 访问过 |
| D | 脏页 |
| C | 缓存属性 |

A/D 位由硬件或软件维护，用于换页算法（如 LRU 近似）。

## 4. 缺页、换页与工作集

### 4.1 缺页异常

当 PTE 无效或权限不符时，MMU 触发**缺页异常**（page fault）。操作系统：

1. 检查地址是否合法；
2. 分配物理页；
3. 从磁盘/文件读入数据；
4. 更新页表；
5. 返回并重新执行指令。

### 4.2 换页与置换算法

物理内存不足时，操作系统把不常用的页换出到磁盘。常见置换算法：

- FIFO：简单，但有 Belady 异常；
- LRU：理论好，硬件实现成本高；
- Clock：用访问位近似 LRU，实际系统常用；
- 工作集模型：根据近期访问窗口决定驻留页集合。

### 4.3 抖动

如果进程工作集大于可用物理内存，系统会频繁换页，CPU 大部分时间在等磁盘，称为**抖动**（thrashing）。解决办法是增加内存、降低并发度或优化局部性。

## 5. 缓存与虚拟内存的交互

### 5.1 VIPT 与 PIPT

- **PIPT**（Physically Indexed, Physically Tagged）：先翻译再查 Cache，简单但慢；
- **VIPT**（Virtually Indexed, Physically Tagged）：用虚拟地址索引、物理地址比较标签，可与 TLB 并行；
- **VIVT**：虚拟索引、虚拟标签，切换进程需刷 Cache，现代 CPU 少用。

### 5.2 别名问题

VIPT 若索引位超出页内偏移，同一物理页的不同虚拟地址可能映射到不同 Cache 行，产生**别名**（aliasing）。解决办法：

- 限制索引位在页内偏移内（如 4 KiB 页、32 字节 Cache 行，索引位不超过 12 位）；
- 硬件监听（snoop）别名；
- 软件按颜色对齐。

### 5.3 TLB 与 Cache 的时序

典型访存流水线：

1. 用 VPN 查 TLB；
2. 同时用虚拟地址低位查 L1 Cache（VIPT）；
3. TLB 命中后比较物理标签；
4. TLB 未命中则 page walk，再重试。

TLB 命中时，地址转换与 Cache 索引可以并行，这是 L1 访问延迟能保持 3–5 周期的关键。

## 6. 保护、共享与内存映射

### 6.1 权限保护

PTE 的 R/W/X、U/S 位由 MMU 检查。用户态访问内核页、写只读页、执行不可执行页都会触发异常。NX（No-eXecute）位是现代系统防止代码注入的重要机制。

### 6.2 共享内存与写时复制

多个进程可以把同一物理页映射到各自虚拟地址：

- 只读共享：代码段、共享库；
- 写时复制（COW）：`fork` 后父子进程共享页，任一方写入时才复制；
- 共享内存：进程间通信的高效方式。

### 6.3 内存映射文件

`mmap` 把文件映射到虚拟地址空间，访问文件像访问内存；缺页时由操作系统按页读入。数据库、加载器、动态链接器都大量使用。

## 7. 与 CPU/OS 的接口

- **页表基址寄存器**：如 x86 的 CR3、RISC-V 的 `satp`，切换进程时更新。
- **ASID/PCID**：给 TLB 项打地址空间标识，避免切换进程时全量刷新 TLB。
- **异常与中断**：缺页、保护错误、TLB 未命中都通过异常机制交给操作系统。
- **内存屏障与页表同步**：修改页表后需要刷新 TLB（`sfence`/`tlbi`），并保证多核可见性。

这些机制与 [3.14 存储层次与缓存一致性](3.14-存储层次与缓存一致性.md) 的 MESI、[4.16 SoC设计](../../04-集成电路设计/芯片设计/4.16-SoC设计.md) 的地址映射、[6.11 嵌入式系统、操作系统与编译基础](../../06-专题与实战/专题/6.11-嵌入式系统-操作系统与编译基础.md) 的启动与内存管理直接相关。

## 小结

- 虚拟内存提供隔离、重定位、容量扩展与共享，核心是页表与 MMU。
- TLB 是页表项的高速缓存，命中率直接影响访存性能；多级页表与大页是容量与速度的折中。
- 缺页异常与置换算法把物理内存扩展成更大的虚拟空间，但工作集过大会抖动。
- VIPT Cache 可与 TLB 并行，但要注意别名；ASID/PCID 减少进程切换的 TLB 刷新。
- 保护位、COW、mmap 是操作系统内存管理的三大常用机制。
