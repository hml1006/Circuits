# 18.2 流水线处理器

> **前置知识**：[18.1 从逻辑门到单周期处理器](18.1-从逻辑门到单周期处理器.md)（单周期数据通路）。本节将其切段流水化，并处理流水线带来的冒险问题——这是进入19章超标量微架构的最后一级台阶。

---

## 1. 流水线：切分与重叠

### 1.1 切成五段

沿用18.1的延迟数据，把单周期切成5段，每段之间插入流水线寄存器：

```
IF     ID     EX     MEM    WB
取指   译码   执行    访存   写回
2      1      2       4      1        ← 各段延迟
```

```
时钟周期 →   1    2    3    4    5    6    7    8    9
指令1:      [IF] [ID] [EX] [MEM][WB]
指令2:           [IF] [ID] [EX] [MEM][WB]
指令3:                [IF] [ID] [EX] [MEM][WB]
指令4:                     [IF] [ID] [EX] [MEM][WB]
                                ↑ 充满后每周期完成一条指令
```

### 1.2 性能计算

- 时钟周期 = 最慢段的延迟 = 4（访存段），不再是10
- 吞吐量：稳态下**每周期完成一条指令**（IPC = 1）
- 加速比（理想）= 段数（受最慢段限制，实际达不到）

**代价**：每段之间的流水线寄存器增加面积和（setup时间带来的）延迟；指令总延迟反而略微增加。

### 1.3 流水线寄存器

段间寄存器锁存该段的所有结果和下游需要的控制信号：

```
IF/ID寄存器:  指令字、PC+4
ID/EX寄存器:  读出的寄存器数据、立即数、控制信号
EX/MEM寄存器: ALU结果、写数据、访存控制
MEM/WB寄存器: 加载的数据、写回目标
```

## 2. 冒险：流水线的三种故障

### 2.1 结构冒险（Structural Hazard）

**同一硬件被两段同时需要**。经典案例：单端口存储器同时被IF（取指令）和MEM（访数据）使用。

```
周期4: 指令3的IF 和 指令1的MEM 争同一个存储器 → 冲突
```

**解决**：哈佛结构——指令存储器与数据存储器分离（现代CPU的L1 I-cache/D-cache分离即源于此）。

### 2.2 数据冒险（Data Hazard）

**后一条指令需要前一条还没写回的结果**：

```
add x1, x2, x3    ; x1 在周期5(WB)才写回
sub x4, x1, x5    ; 周期3(ID)就要读 x1 → 读到旧值！
```

#### 解法一：转发（Forwarding/Bypass）

ALU结果其实周期3(EX结束)就有了，不必等WB。加一条旁路路径直接送到下一条指令的ALU输入：

```
EX/MEM寄存器的ALU结果 ──(转发多选器)──→ 下一条指令的ALU输入
MEM/WB寄存器的结果    ──(转发多选器)──→ 更后面指令的ALU输入
```

**转发判定逻辑**：

```
if (EX/MEM.RegWrite && EX/MEM.rd != 0 && EX/MEM.rd == ID.rs1)
    ALU输入1 ← 转发EX/MEM的结果
```

#### 解法二：加载-使用冒险必须停顿一拍

```
lw  x1, 0(x2)     ; 数据周期4(MEM末)才有
add x3, x1, x4    ; 周期4(EX)就要用 → 转发也来不及！
```

**解决**：硬件插入一个"气泡"（stall），配合转发：

```
lw  x1, 0(x2)     [IF][ID][EX][MEM][WB]
气泡(bubble)                    [--][--]        ← 冻结PC和IF/ID寄存器
add x3, x1, x4         [IF][ID][stall][EX][MEM][WB]
                                        ↑ MEM/WB→EX转发
```

编译器调度（重排指令填空泡）可消除大部分此类停顿。

### 2.3 控制冒险（Control Hazard）

**分支指令到EX/MEM才知道方向，取指早已走远**：

```
beq x1, x2, target   [IF][ID][EX]  ← 周期3才知是否跳转
下一条指令?           [IF][ID]     ← 周期1就得决定从哪取！
```

**解法梯队**（19.1节分支预测的完整展开正是从这里出发）：

| 层级 | 方法 | 代价 |
|------|------|------|
| 最保守 | 停顿到分支结果出来 | 每次3周期气泡 |
| 简单 | 静态预测（向后跳/向前不跳） | 循环友好 |
| 实用 | 2位饱和计数器 + BHT | 90~95%准确 |
| 现代CPU | TAGE/ITTAGE/多级BTB | 99%+（见19.1） |
| 编译器 | 延迟槽（早期MIPS）/ 调度 | 部分隐藏 |

**误预测代价** = 分支解析周期数 ≈ 流水线前端深度。这解释了为什么深流水线（19章的17~19级）必须配极准的预测器。

## 3. 分支提前与高级优化（通往超标量）

### 3.1 把分支判定移到ID段

在ID段加一套专用比较器，分支在周期2就解析——误预测代价从3降到1。代价：ID段变复杂、又产生新的数据冒险（分支比较依赖前序ALU结果时需要专用转发）。

### 3.2 更宽的发射：超标量

五级流水线IPC上限=1。突破方法：

- **多发射**：每周期取指/译码/发射N条 → 19.1的超标量
- **乱序执行**：让不相关的指令越过停顿的指令 → 19.1的Tomasulo
- **推测执行**：预测分支后提前执行 → 19.1的推测与恢复

### 3.3 更深的流水线：超流水

把每段再切细提高主频——但每段流水线寄存器开销占比上升，且误预测代价增大。Pentium 4的31级深流水线（见19.1表）就是走极端的教训。

## 4. 五级流水线 vs 现代CPU

| 特性 | 经典五级 | 现代超标量（19章） |
|------|---------|------------------|
| 发射宽度 | 1 | 6~10 |
| 执行顺序 | 按序 | 乱序（ROB提交） |
| 分支处理 | 停顿/静态预测 | 多级预测器+推测执行 |
| 数据冒险 | 转发+停顿 | 寄存器重命名消除伪依赖 |
| 加载延迟 | 1段 | L1命中4~5周期，乱序隐藏 |
| IPC | ≤1 | 4~6 |

**五级流水线是骨架，超标量是在骨架上长出的器官**——19.1将逐个展开这些器官。

## 5. 本节要点

| 概念 | 一句话总结 |
|------|-----------|
| 流水线 | 切段重叠，稳态IPC=1，时钟由最慢段决定 |
| 结构冒险 | 硬件冲突 → 资源复制（I/D分离） |
| 数据冒险 | 转发解决大部分，加载-使用仍需1拍停顿 |
| 控制冒险 | 分支预测准确率决定深流水线的生死 |
| 下一站 | 多发射+乱序+推测 = 超标量（19章） |
