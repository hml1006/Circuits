# 4.53 芯片测试与硅后验证

> **本章定位**：连接 DFT、量产测试与首片调试，说明 ATE 能发现什么、不能证明什么，并给出从首次上电到失效分析、量产良率闭环的可执行方法。
>
> **前置知识**：**必需** [4.15 可测性设计（DFT）](4.15-可测性设计-DFT.md)与[4.52 数字设计签核与可制造性](4.52-数字设计签核与可制造性.md)；**推荐** [4.38 封装与热设计（一）](../封装与热设计/4.38-封装与热设计-封装技术.md)–[4.39 封装与热设计（二）](../封装与热设计/4.39-封装与热设计-热管理与可靠性.md)，用于理解封装互连、散热和热可靠性对测试与硅后结果的影响。

## 1. 测试、硅后验证与可靠性的分工

- **制造测试**回答器件是否含有可检测制造缺陷、是否满足规定的测试限值，追求稳定、快速和可重复。
- **硅后验证/确认**回答真实芯片在板级和系统条件下是否实现设计意图，包括功能、性能、接口互操作和余量。
- **可靠性评价**回答器件在应力与时间作用下是否保持性能，关注早期失效、寿命、退化及环境鲁棒性。
- **失效分析（FA）**从失效电学特征出发定位物理或设计原因，再将结论反馈到设计、工艺、封装或测试。

四者共享数据但不能互相替代。ATE 全部通过不证明系统场景无缺陷；首片功能正常不证明批量良率；HTOL 通过也不证明没有功能漏洞。

## 2. ATE 测试项与测试成本

### 2.1 常见测试项

| 测试项 | 主要目的 | 典型注意事项 |
|---|---|---|
| 接触、开短路与引脚连续性 | 发现探针/封装连接、I/O 结构异常 | 先排除接触电阻、探针污染和负载板连接问题 |
| 泄漏与静态电流 | 筛查结、栅氧、电源域和异常导通问题 | 必须固定温度、电压、复位和引脚状态；先进工艺下不能只看单一 IDDQ 门限 |
| Scan chain 与 ATPG | 检查链完整性，检测固定型、跳变等模型化逻辑故障 | 关注压缩、X 屏蔽、捕获时钟及覆盖范围 |
| MBIST 与存储器修复 | 检测存储阵列故障，执行诊断或冗余修复 | 算法、地址映射、比较器、修复写入和修复后复测都要验证 |
| 时钟与 PLL | 检查锁定、频率、分频和关键时钟参数 | “lock=1”不等于输出频率、抖动和占空比全部合格 |
| I/O 与高速接口 | 检查驱动、电平、时序、回环或链路训练 | ATE 负载与真实通道不同，需与板级结果相关 |
| 模拟宏单元与 trim | 测量偏置、基准、数据转换等参数并校准 | 保存校准码、条件和残差，不能仅记录“已校准” |
| 功能与性能测试 | 在规定条件下检查关键功能和速度/功耗等级 | 测试程序覆盖的是指定场景，不等同于完整系统验证 |

测试限值应来自设计规格、特性数据和量产能力共同评审。过宽会造成漏筛，过窄会误杀良品；未经相关分析，不能把单次 bench 的最佳值直接变成 ATE 门限。

### 2.2 成本由什么构成

单颗测试成本可用下式组织估算，而不是套用行业固定比例：

$$C_{unit}\approx\frac{(t_{test}+t_{index})R_{cell}}{N_{eff}}+C_{consumable}+\frac{C_{development}}{N_{unit}}+C_{retest}$$

其中 $R_{cell}$ 包含测试机及配套设备的时间成本，$N_{eff}$ 是考虑多site效率和良率后的有效并行数，耗材包括探针卡、负载板等，开发成本包括程序、硬件和调试验证。

降低成本的主要手段是缩短向量与测试时间、提高多site效率、减少无效复测和改善良率。直接删测试可能增加测试逃逸、客户退货和诊断成本，应以故障覆盖率、缺陷数据和风险为依据。

## 3. Scan/MBIST 的能力边界

[4.15](4.15-可测性设计-DFT.md)介绍了扫描、ATPG 和 BIST。使用这些结果时，应明确分母和未覆盖对象：

1. **Scan 不是功能验证**：高固定型/跳变故障覆盖率只说明对所选故障模型的检测能力，不证明时序协议、软件交互或模拟功能正确。
2. **覆盖率不是零缺陷承诺**：未建模开路、桥接、参数缺陷、模拟宏和未可控逻辑仍可能遗漏；测试覆盖与故障覆盖的定义也不能混用。
3. **压缩与屏蔽会损失可观测性**：chain fail、X source 和 mask 需要审查，否则“pass”可能只说明响应被遮住。
4. **MBIST 针对存储器模型**：March 等算法覆盖特定固定、跳变、耦合等故障，不自动覆盖全部外围逻辑、系统总线和实际并发访问。
5. **修复是另一段流程**：冗余分析、熔断/OTP 写入、掉电保持和修复后复测必须闭环，不能把“找到坏地址”当作“已修复”。

存储器故障模型、March、ECC 与修复可进一步参阅[4.37.5 存储器可靠性与测试](../存储器IC设计/4.37.5-存储器可靠性与测试.md)。

## 4. 量产测试：CP、FT 与 SLT

| 阶段 | 对象与目的 | 优势 | 局限与数据用途 |
|---|---|---|---|
| CP（Circuit Probe，晶圆测试） | 封装前用探针接触 die，筛选电性和制造缺陷 | 较早剔除坏 die，保留晶圆坐标 | 探针接触、测试温度和高速负载受限；晶圆图可揭示边缘、中心或局部工艺特征 |
| FT（Final Test，成品测试） | 封装后按产品规格筛选并分档 | 覆盖封装互连和最终产品测试条件 | 成本较高；需分析批次、封装、site 和测试程序相关性 |
| SLT（System Level Test，系统级测试） | 在接近真实系统的硬件、固件和负载下运行 | 可发现高速接口、软硬件交互和部分ATE逃逸 | 单颗时间长、故障定位粗，不能无依据替代全部结构测试 |

测试流程要定义首测、复测、返工后测试和放行规则。复测用于确认接触等可恢复因素时，应保留首次结果和原因，禁止用反复测试的“最好一次”掩盖间歇失效。

### 4.1 Binning

Binning 将合格器件按频率、功耗或其他已定义规格分档。每个 bin 必须有独立、可审计的限值和追溯记录，并满足对应产品的全部强制测试。不能把关键安全参数不合格的器件改名后放行，也不能只看平均性能而忽略分布尾部。

### 4.2 Shmoo

Shmoo 是在一个或多个条件轴上扫描并记录 pass/fail 边界的工具，常用轴包括电压、频率、温度、接口时序和驱动强度。执行时应：

1. 先确认基准条件、测试内容和设备误差，再逐轴或按设计好的网格扫描；
2. 保存首败点、失败签名和全部环境条件，而不只保存一张着色图；
3. 在边界附近复测，并跨样本、温度或板卡比较，区分随机接触问题与真实余量；
4. 将 shmoo 用于诊断、特性分析和 guardband 讨论，不能直接把单次边界当作量产门限。

shmoo 图上的“通过区”只对该样本、负载和测试程序有效，不等于整个产品寿命与批量的保证区。

## 5. HTOL、ESD、LU 与可靠性评价

| 项目 | 施加的应力与问题 | 与量产测试的区别 |
|---|---|---|
| HTOL | 在规定温度、电压和工作负载下进行时间加速，观察退化与寿命相关失效 | 通常是抽样可靠性评价，不是每颗芯片的一次功能测试；条件与样本量按产品要求确定 |
| ESD（如 HBM/CDM） | 模拟静电放电，评价保护网络和损伤阈值 | 面向搬运、装配等静电事件，不用来替代寿命试验 |
| LU（Latch-up） | 通过过压、电流注入等条件检查寄生闩锁及持续大电流风险 | 面向特定触发机制，需防止试验本身造成无关损坏 |
| Burn-in 筛选 | 用偏压和温度加速暴露早期缺陷 | 目的可偏重量产早期失效筛选，不能直接把应力时间换算成通用寿命 |

可靠性是随时间、环境和应力维持规定性能的能力；HTOL、ESD、LU 只是其中不同机理的评价手段。加速模型、置信度、样本代表性和失效判据必须同时给出，详见[6.7 可靠性与失效分析](../../06-专题与实战/专题/6.7-可靠性与失效分析.md)。

## 6. Bring-up 计划：从可控上电到系统负载

### 6.1 上电前准备

- 固化芯片批次、晶圆/封装信息、网表与掩膜版、固件、寄存器表和已知 errata；
- 准备原理图、电源树、复位树、时钟树、测试点、原理图与板图版本，以及 golden board/样品策略；
- 核对焊接方向、供电顺序、去耦、上下拉、未用引脚处理和散热；
- 准备限流电源、示波器/逻辑分析仪、JTAG、最小固件和统一日志模板；
- 定义每一步的进入条件、通过判据、异常断电阈值与负责人，不在故障现场临时改变所有变量。

### 6.2 分层推进

**电源与复位**：先不装芯片或断开负载检查板级供电，再按顺序上电，记录每路电压、浪涌、稳态电流和复位波形。过流、冒烟、异常发热或失控闩锁迹象应立即断电并保留现场。

**JTAG 与寄存器**：先验证 TAP 复位、IDCODE/BYPASS 和链路完整性，再读安全只读寄存器。检查复位默认值、读写掩膜、位清晰/置位语义、总线错误和保留位；不要一开始批量写入未知全局控制寄存器。

**时钟与电源状态**：确认参考时钟后再检查 PLL lock、实际输出频率、分频和时钟使能。逐个电源域和时钟域打开模块，记录空闲、工作和低功耗状态电流，并监测电压纹波与温度。DVFS 应按已知安全序列单步推进。

**接口与功能**：先做内部回环，再做外部回环和真实链路；使用已知图案检查训练、误码、溢出和恢复。随后运行最小软件、单模块场景，最后才进入多模块并发、压力、低功耗切换和长时间运行。

每一步都保存通过证据。跳过上电、JTAG 或寄存器检查直接跑完整系统，会把多个故障叠加成难以定位的“芯片不工作”。

## 7. 可执行硅后检查表

| 完成 | 步骤 | 操作与记录 | 通过/转向 |
|---|---|---|---|
| [ ] | P01 样品身份 | 记录 lot、wafer/die 或封装码、板卡、固件和测试程序版本 | 信息不全先补齐，否则禁止跨样品下结论 |
| [ ] | P02 断电检查 | 查焊接、方向、短路、上下拉、散热和测试点 | 异常先修板，不用上电验证猜测 |
| [ ] | P03 分路上电 | 按规定顺序限流上电，保存电压、电流、复位和温度波形 | 超出项目安全判据立即断电并隔离样品 |
| [ ] | P04 JTAG | 检查 TAP reset、IDCODE、BYPASS 与稳定通信 | 失败则查供电、复位、TCK/TMS、上拉和链路，不直接判死片 |
| [ ] | P05 寄存器 | 核对默认值、合法读写、保留位和错误响应 | 失败保存地址、数据、时序和总线状态 |
| [ ] | P06 时钟 | 检查参考时钟、PLL lock、实际频率、分频与门控 | 失败停在最小时钟配置，不继续提高负载 |
| [ ] | P07 电源状态 | 逐域开关并记录静态/动态电流、纹波和温度 | 异常按电源域二分，检查序列与焊接/损伤 |
| [ ] | P08 DFT/存储器 | 在适用模式运行 chain、scan 或 MBIST，保存失败日志 | 与 CP/FT 结果相关，不用 pass 替代功能检查 |
| [ ] | P09 接口 | 依次做内部回环、外部回环、真实链路和已知图案测试 | 保存首败计数、通道、速率与训练状态 |
| [ ] | P10 最小功能 | 运行最小固件和单模块定向用例 | 失败则缩小到寄存器、时钟、数据路径最小组合 |
| [ ] | P11 条件扫描 | 对疑难点执行受控电压/频率/温度 shmoo | 记录边界与重复性，不把单点结果外推批量 |
| [ ] | P12 系统压力 | 加入并发、错误注入、低功耗切换与长时运行 | 保存首败时间和事件序列，关闭无关变量复现 |
| [ ] | P13 归档分诊 | 汇总日志、波形、样品去向和待办 | 可复现后进入定位；不可复现则加强触发与观测 |

## 8. 故障分诊流程

```text
安全停机并保存现场
        ↓
固定版本与环境，确认能否复现
        ↓
按层级分类：供电/复位 → JTAG/寄存器 → 时钟 → 接口 → 功能/性能
        ↓
最小用例 + 单变量实验 + golden 样品/板卡交叉替换
        ↓
必要时 shmoo、scan/MBIST 诊断、CP/FT 数据相关
        ↓
形成可检验假设 → 无损/破坏性 FA → 根因验证 → 修复与回归
```

不可复现不等于“没有问题”。应记录首败时间、温度、电压、软件事件和电源状态，增加触发器、错误计数器或快照，重点排查间歇接触、热、时序余量和异步竞争。

交叉替换应区分芯片随板走、故障随芯片走或只在特定组合出现。每次只改变一个变量，并保留原配置；同时换板、换固件、换电源会破坏因果关系。ATE 与 bench 不一致时，先对齐测试模式、向量、时序、负载、温度和限值，再讨论测试逃逸。

## 9. 失效定位与 FA 闭环

1. **电学定位**：利用 scan failure log、链/单元诊断、MBIST 地址位图、接口误码位置和寄存器快照缩小范围；诊断候选不是物理根因证明。
2. **无损检查**：先做外观、X 射线、声学扫描、热/发光或其他适用观测，保护后续分析证据。
3. **进一步定位**：根据机理选择曲线追踪、热成像/热点、光子发射或激光扫描等手段；设备结果必须与失效电学特征相互印证。
4. **破坏性分析**：开封、去层、切片或 FIB 应经样品与证据评审后执行，并保留对照样品。
5. **根因验证**：发现的裂纹、桥接或异常只有能解释失效签名、复现机制或经对照验证，才可升级为根因。
6. **纠正与预防**：明确临时遏制、受影响批次、设计/工艺/封装/测试修改、回归范围和量产监控项；FA 报告不能只停在“发现异常”。

可靠性机理和完整 FA 方法见[6.7](../../06-专题与实战/专题/6.7-可靠性与失效分析.md)，存储器阵列问题还应与[4.37.5](../存储器IC设计/4.37.5-存储器可靠性与测试.md)中的测试与修复结果联合分析。

## 10. 量产数据、SPC 与良率

### 10.1 数据组织

以唯一器件身份串联 CP、FT、SLT、复测、bin、封装批次和现场返回，至少保留测试条件、程序版本、site、时间、首测/终测结果及失效项。常用分析包括：

- CP 晶圆图的中心/边缘、环状、条带、局部簇和重复版图位置特征；
- 按 lot、wafer、封装批次、测试机、site 和时间的 Pareto 与相关性；
- 参数分布、bin 迁移、首通过率、最终通过率和复测恢复率；
- ATE fail、SLT fail 与现场返回的对应关系，用于发现测试空洞或过杀。

首通过率与最终良率应分开统计，复测器件不能当成新增合格投入。多阶段累计良率使用各阶段的**条件良率**相乘，前提是样品口径一致且追溯完整。

### 10.2 SPC 不等于规格检查

SPC 用稳定过程数据建立控制界限，识别特殊原因波动；规格限来自产品要求。二者不能混用：过程“受控”仍可能持续生产出超规格产品，过程偶尔出控制界限也不等于每颗芯片都失效。

异常处理流程是报警、确认量测系统、隔离影响范围、查找特殊原因、验证纠正措施并重新观察稳定性。不能通过删尾点、扩大限值或选择性复测让图表“恢复正常”。设计改进则应观察缺陷 Pareto、参数分布和现场失效率是否持续变化，而非只看一批良率。

## 小结

1. ATE、硅后验证和可靠性试验回答不同问题，任何单项通过都不是全生命周期正确性的证明。
2. Scan/MBIST 面向特定制造故障模型，必须说明覆盖范围、屏蔽、修复和复测边界。
3. CP、FT、SLT 各有成本与诊断能力；binning、shmoo 和复测都需要可审计规则。
4. Bring-up 应按供电、JTAG、寄存器、时钟、电源状态、接口和系统负载分层推进，并保存首败证据。
5. FA 要从电学签名走到经验证根因，再反馈到设计、工艺、封装和测试。
6. 量产良率与 SPC 依赖一致追溯和稳定统计口径，控制界限不能替代产品规格。
