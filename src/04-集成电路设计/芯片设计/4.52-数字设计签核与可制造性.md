# 4.52 数字设计签核与可制造性

> **本章定位**：把 RTL、网表、约束和物理实现收敛为可审查、可复现的流片签核证据，重点处理 Lint、CDC、RDC、约束以及 DFM/DFY，而不是重复功能验证。
>
> **前置知识**：**必需** [4.5 RTL设计：基础语法与建模](4.5-RTL设计-基础语法与建模.md)、[4.6 RTL设计：FSM与流水线](4.6-RTL设计-FSM与流水线.md)、[4.7 RTL设计：综合与FPGA](4.7-RTL设计-综合与FPGA.md)、[4.8 RTL设计：SystemVerilog与Chisel](4.8-RTL设计-SystemVerilog与Chisel.md)、[4.9 功能验证](4.9-功能验证.md)、[4.10 逻辑综合](4.10-逻辑综合.md)、[4.11 物理设计](4.11-物理设计.md)、[4.12 时序分析](4.12-时序分析.md)，即 4.5–4.12；**推荐** [4.14 版图设计](4.14-版图设计.md)，用于理解密度、通孔和天线等物理检查。

## 1. 签核的目标与证据链

数字设计签核不是“某个工具运行结束”，而是针对指定版本和工作条件给出可追溯结论：什么设计，在什么模式、工艺角、电压和温度下，依据哪些规则与例外，满足哪些交付要求。

一次可复现的签核至少绑定以下输入：

- RTL、综合网表或布局布线后网表的版本与校验值；
- 时钟、I/O、模式、时序例外和物理约束；
- 标准单元库、存储器模型、互连寄生与工艺规则版本；
- 检查配置、过滤规则、未豁免错误和已批准 waiver；
- 报告、问题责任人、修复记录以及修复后的回归结果。

功能仿真通过并不能替代结构签核。例如，仿真可能看不到多驱动网表的实际竞争、异步采样的亚稳态，也不能证明版图具有足够制造冗余。反过来，Lint 或 CDC 报告为零也不证明功能正确。

## 2. Lint：先消除结构歧义

Lint 应在 RTL 阶段持续运行，并在综合网表和每次 ECO 后按适用规则重跑。RTL 的对应概念可回顾 [4.5](4.5-RTL设计-基础语法与建模.md)，FSM 与流水线的时序意图可回顾 [4.6](4.6-RTL设计-FSM与流水线.md)。

| 检查项 | 典型风险 | 审查与修复要点 |
|---|---|---|
| 多驱动 | 两个过程或模块驱动同一变量，网表可能出现竞争或非预期三态 | 明确唯一所有者；内部三态和芯片 I/O 三态分开审查，不能一键屏蔽 |
| 推断 latch | 组合逻辑分支赋值不完整，产生非预期保持状态和额外时序路径 | 给所有分支默认赋值；若确为 latch 设计，注明相位、时序与测试意图 |
| 位宽与符号 | 截位、扩位、隐式有符号转换使比较或运算结果偏离意图 | 显式标注宽度和符号，检查移位量、常量、拼接及溢出位 |
| 未使用信号 | 端口接错、逻辑被优化、调试或 DFT 信号遗漏 | 区分真正死代码与有意保留项；同时检查未驱动输入和悬空输出 |
| 组合环与 incomplete case | 仿真与综合解释不同，或形成不受控振荡和保持 | 消除环路与歧义分支，不能只依赖仿真中的初值或 `case` 覆盖假设 |

waiver 必须包含规则、对象范围、技术理由、责任人和复审条件。“历史问题”“工具太吵”不是理由。对位宽告警做显式强制转换前，还要证明转换后的语义正确；否则只是把缺陷变成静音。

## 3. CDC：跨时钟域不仅是加两级触发器

### 3.1 双触发同步器的能力边界

单比特、变化足够慢的异步电平常用两级触发器降低亚稳态传播概率：

```systemverilog
always_ff @(posedge dst_clk or negedge dst_rst_n) begin
  if (!dst_rst_n) {sync_ff2, sync_ff1} <= '0;
  else            {sync_ff2, sync_ff1} <= {sync_ff1, async_in};
end
```

它有以下明确边界：

- **不消除亚稳态**：只给第一级更多解析时间，第二级仍非数学意义上的绝对安全；
- **不保证捕获短脉冲**：源脉冲若未被目的时钟采到，增加触发器级数也无济于事，应先展宽或改用握手；
- **不适合直接同步多位数据**：各位可能采自不同源时刻，组合出从未存在过的数据；
- **不允许随意插入组合逻辑**：同步级间的逻辑会压缩解析时间并引入毛刺，专用同步单元及其约束应按流程使用；
- **不修复复位、上电和协议错误**：这些条件需要 RDC 与系统时序共同验证。

常用近似模型可写为

$$\mathrm{MTBF}_{sync}\approx\frac{e^{T_r/\tau}}{K f_c f_d}$$

其中 $T_r$ 是第一级可用的解析时间，$\tau$ 与触发器工艺有关，$f_c$ 为目的时钟频率，$f_d$ 为异步输入有效变化率，$K$ 为模型系数。这里的 MTBF 是**特定同步事件模型下的平均失效间隔估计**，不是整芯片可靠性寿命；参数必须来自适用库或表征流程，不能套用通用固定数值。高数据率、多同步器和多任务并发还需汇总系统风险。

### 3.2 握手：用确认换取事务完整性

四相握手适合低频控制或多位捆绑数据。下面片段省略两个常规双触发同步器：`req_d_sync` 是目的域中的请求，`ack_s_sync` 是源域中的确认。

```systemverilog
// 源域：只在上一轮完全结束后发起，并保持 data_s 至确认返回
if (send && !req_s && !ack_s_sync) begin
  data_s <= payload;
  req_s  <= 1'b1;
end else if (req_s && ack_s_sync) begin
  req_s  <= 1'b0;
end

// 目的域：看见请求后采样稳定数据，再返回确认
always_ff @(posedge dst_clk or negedge dst_rst_n) begin
  if (!dst_rst_n) ack_d <= 1'b0;
  else if (req_d_sync && !ack_d) begin
    data_d <= data_s;
    ack_d  <= 1'b1;
  end else if (!req_d_sync) begin
    ack_d  <= 1'b0;
  end
end
```

审查时不能只看波形“成功一次”，还要验证：源在确认返回前不撤数据；新事务等待确认撤销；目的侧只消费一次；任一侧复位、暂停或超时后不会形成假事务。吞吐不足时可采用全握手或其他流控，但不得用固定延迟猜测“数据已经稳定”。

### 3.3 异步 FIFO 与 Gray 指针

异步 FIFO 用双端口存储器传递数据，用跨域同步的读写指针判断空满。指针采用 Gray 码，使正常递增时每次只有一位变化；**数据总线不经过双触发器逐位同步**。

以下为写域核心片段，指针宽度为 `AW+1`，对应深度 $2^{AW}$，示例取 `AW>=2`：

```systemverilog
function automatic logic [AW:0] bin2gray(input logic [AW:0] b);
  return (b >> 1) ^ b;
endfunction

always_ff @(posedge wclk or negedge wrst_n) begin
  if (!wrst_n) begin
    wbin <= '0; wgray <= '0;
  end else if (wen && !wfull) begin
    wbin  <= wbin + 1'b1;
    wgray <= bin2gray(wbin + 1'b1);
  end
end

always_ff @(posedge wclk or negedge wrst_n) begin
  if (!wrst_n) {rgray_w2, rgray_w1} <= '0;
  else         {rgray_w2, rgray_w1} <= {rgray_w1, rgray};
end
```

读域对本地读指针执行同样的二进制/Gray 更新，并将写 Gray 指针同步到读域。空标志比较“下一读 Gray”与同步写 Gray；常用满标志将下一写 Gray 与 `{~rgray_w2[AW:AW-1], rgray_w2[AW-2:0]}` 比较。空满判断允许因同步延迟而保守，却不允许溢出或下溢。

FIFO 签核还需证明：

- 深度、指针额外位和满比较公式匹配，非二次幂深度不能照搬上述满判据；
- 写数据和地址稳定后，才发布可被读域观察到的写指针；
- 读写指针同步链路有适当的延迟、偏斜和物理约束，不能把所有 Gray 位一概设为 false path；
- 随机异步频率、背靠背读写、环绕、同时空满边界和两侧复位顺序均经过验证；
- 形式检查或断言覆盖不溢出、不下溢、数据顺序和指针只单向推进等性质。

### 3.4 Reconvergence：分开正确，汇合仍可能错误

多个相关异步信号各自经过同步器，在目的域重新组合时称为 reconvergence 风险。即使每条路径都“CDC 合规”，不同路径的采样延迟仍可能不同，使 `valid` 与 `data`、读写使能或分支选择彼此错位。

处理原则是保留事务关系：多位数据采用握手捆绑、异步 FIFO 或具有明确稳定窗口的 bundled-data；独立控制位只有在协议证明其任意先后组合都安全时，才允许分别同步。相关信号汇合后的断言比单条同步链更能说明系统正确性。

## 4. RDC：复位也是跨域控制网络

复位树审查要列出 POR、外部复位、看门狗、软件复位、调试复位及各电源域复位的来源、作用范围、断言条件和释放顺序。仅有时钟域图而没有复位域图，无法判断哪些逻辑会在另一半仍复位时开始工作。

对异步置位/复位，常见策略是**异步断言、同步释放**：

- 断言可立即让电路进入安全态，不必等待时钟；
- 释放由本时钟域同步，降低在时钟有效沿附近撤回复位所造成的 recovery/removal 违例；
- 每个时钟域使用自己的释放同步器，并检查复位树缓冲延迟和最小复位脉宽；
- 若某块只允许同步复位，则必须另行证明复位有效期间时钟存在且脉宽可采样。

RDC 关注源和目的使用不同复位的路径。例如源域仍在复位而目的域已运行，目的逻辑可能把复位初值或释放跳变当作有效数据。可选措施包括同时复位接收端、先静默再按顺序释放、隔离无效数据、用握手确认双方就绪；不能不加分析地在每条 RDC 路径上加同步器。

## 5. 约束与时序签核

[4.10 逻辑综合](4.10-逻辑综合.md)和[4.11 物理设计](4.11-物理设计.md)都依赖约束，最终则应按[4.12 时序分析](4.12-时序分析.md)检查实现后的全部适用模式与工艺角。

1. **时钟完整**：主时钟、生成时钟、门控时钟和测试时钟定义一致，频率、波形和不确定度有来源。
2. **模式互斥明确**：功能、扫描、旁路及低速调试模式使用正确的 clock group 或 case analysis，不把互斥误当异步。
3. **接口有预算**：输入/输出延迟、驱动与负载对应真实外部时序；片上高速接口还需源同步等专门约束。
4. **例外逐条证明**：false path、multicycle path 和 max/min delay 均有协议或结构依据，禁止用大范围通配符掩盖违例。
5. **CDC/RDC 约束不越位**：静态时序不证明同步协议正确，异步路径也不能仅因设为 false path 就视为安全。
6. **报告没有盲区**：检查未约束端点、未检查路径、setup/hold、recovery/removal、最小脉宽和时钟门控；寄生与串扰设置须符合该阶段流程。

约束文件本身也要评审和回归。修复一个模式的违例后，应重跑受影响的所有模式与工艺角，而非只保存一张“最差路径已通过”的截图。

## 6. DFM/DFY：能制造与制造得好的区别

[4.13 功耗分析](4.13-功耗分析.md)关注工作条件下的功耗与电源完整性，[4.14 版图设计](4.14-版图设计.md)给出几何实现基础；DFM/DFY 则进一步考虑工艺波动、缺陷和图形环境。

### 6.1 可制造性、DFM 与 DFY

- **可制造性**是设计能否在给定工艺窗口内被稳定制造的属性；DRC/LVS 通过是必要条件，但不是高良率保证。
- **DFM（Design for Manufacturability）**通过满足制造规则、改善图形环境和降低工艺敏感性，使设计更容易制造。
- **DFY（Design for Yield）**更直接面向良率损失机理，例如缺陷受限良率、参数受限良率和冗余修复，并用数据评估面积、性能与良率的权衡。
- **良率**是投入与合格产出之间的统计结果，还受工艺控制、测试限值和缺陷分布影响；它不是某次 DRC 报告中的布尔结论。

因此，“可制造”不等于“每批都有目标良率”，“良率低”也不能未经分析就归咎于设计。工艺漂移、测试误判和封装损伤需要分开归因。

### 6.2 重点检查

**冗余 via/contact**：在规则允许的位置增加并联连接，降低单个接触失效的影响。自动插入后仍需检查电流密度、寄生、可布通性及局部密度，不能认为数量越多越好。

**密度与填充**：金属、多晶或有源区密度及梯度影响刻蚀和 CMP。dummy fill 应使用批准流程，并在填充后重新提取寄生、检查时序和天线；新增填充可能改变敏感互连耦合。

**天线效应**：长互连在制造等离子过程中可能积累电荷并损伤栅氧。按 foundry 天线规则检查各层比值，采用向上跳线或合适的天线二极管等办法泄放；修复后重跑连接性和物理验证。

**其他良率敏感项**：推荐规则、光刻热点、线端与拐角、冗余/修复策略和参数分布应结合工艺数据审查。这里不提供跨工艺通用的固定密度、天线比值或冗余数量。

## 7. 可执行签核审查清单

下表的“完成”必须有报告或设计证据，而不是口头确认；任一修复都触发对应回归。

| 编号 | 执行动作 | 通过证据与失败处理 |
|---|---|---|
| S01 | 固化网表、约束、库、规则及配置版本 | 版本清单可复现；输入漂移则重新建立基线 |
| S02 | 运行 RTL/网表 Lint 并逐条分类 | 多驱动、非预期 latch、危险位宽和未用信号均修复或获批 waiver |
| S03 | 导出全部时钟域与跨域路径 | 每条 CDC 都有协议分类，未知路径清零 |
| S04 | 审查双触发同步器输入类型与结构 | 电平适用；短脉冲改握手，多位总线不逐位独立同步 |
| S05 | 检查握手保持、撤销、背压和复位场景 | 断言覆盖事务不丢失、不重复；失败回到协议修复 |
| S06 | 检查 FIFO Gray、空满、环绕和约束 | 异步随机回归及性质检查通过；溢出/下溢必须关闭 |
| S07 | 审查 reconvergence 汇合点 | 相关信号有共同事务机制；无“各自同步即安全”的假设 |
| S08 | 核对 MTBF 模型输入和适用边界 | 参数来源明确，不用未知常数宣称绝对安全 |
| S09 | 画出复位树、复位域和释放顺序 | 每个异步释放都有本域策略，RDC 路径均有处置 |
| S10 | 检查 recovery/removal 和复位期间时钟 | 所有适用模式/工艺角通过；违例修树或修顺序 |
| S11 | 审计 SDC 与所有时序例外 | 无意外未约束路径，每条例外有范围和证明 |
| S12 | 重跑实现后 STA 并检查路径覆盖 | setup/hold、脉宽、门控等报告满足项目准则 |
| S13 | 审查冗余 via、density/fill 和天线报告 | 修复后重跑 DRC/LVS、寄生提取及受影响 STA |
| S14 | 将 DFY 风险与工艺/测试数据对照 | 区分设计与工艺原因，形成可验证的改进项 |
| S15 | 归档报告、waiver、责任人和回归记录 | 所有豁免可复审，流片候选版本与证据一一对应 |

## 小结

1. 签核结论必须绑定设计、约束、库、规则、模式和 waiver，能由他人复现。
2. Lint 消除结构歧义；CDC 依据信号语义选择同步、握手或 FIFO，并检查汇合后的协议。
3. 双触发器只降低亚稳态传播概率；Gray FIFO 还要验证空满、数据稳定、约束和复位。
4. RDC 需要完整复位树和释放顺序；异步断言、同步释放只是常用策略，不替代全芯片证明。
5. DFM 面向可制造性，DFY 面向良率损失机理；DRC 通过不等于量产良率达标。
