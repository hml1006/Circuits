## 1. VIP（Verification IP）

### 1.1 VIP概念与结构

VIP（Verification IP）是针对特定总线协议的、经过验证的可重用验证组件包。一个完整的VIP通常包含：

```
┌──────────────────────────────────────────────────┐
│                    VIP 结构                       │
│                                                  │
│  ┌─────────────────────────────────────────┐     │
│  │           Master Agent                  │     │
│  │  ┌─────────┐ ┌────────┐ ┌───────────┐  │     │
│  │  │ Driver  │ │Monitor │ │ Sequencer │  │     │
│  │  └─────────┘ └────────┘ └───────────┘  │     │
│  └─────────────────────────────────────────┘     │
│                                                  │
│  ┌─────────────────────────────────────────┐     │
│  │           Slave Agent                   │     │
│  │  ┌─────────┐ ┌────────┐ ┌───────────┐  │     │
│  │  │ Driver  │ │Monitor │ │ Sequencer │  │     │
│  │  └─────────┘ └────────┘ └───────────┘  │     │
│  └─────────────────────────────────────────┘     │
│                                                  │
│  ┌──────────────┐  ┌──────────────────────┐     │
│  │  Protocol    │  │  Coverage Model      │     │
│  │  Checker     │  │                      │     │
│  └──────────────┘  └──────────────────────┘     │
│                                                  │
│  ┌──────────────┐  ┌──────────────────────┐     │
│  │  RAL Model   │  │  Register Sequences  │     │
│  └──────────────┘  └──────────────────────┘     │
│                                                  │
│  ┌─────────────────────────────────────────┐     │
│  │        Standard Sequences               │     │
│  │  (reset, sanity, random, stress, etc.)  │     │
│  └─────────────────────────────────────────┘     │
└──────────────────────────────────────────────────┘
```

### 1.2 标准协议VIP

| 协议 | 组织 | 典型应用 | VIP关键特性 |
|------|------|----------|-------------|
| AXI/AXI4 | ARM | SoC内部高速互联 | 突发传输、乱序、多ID |
| AXI-Lite | ARM | 寄存器访问 | 简化版AXI |
| AXI-Stream | ARM | 数据流传输 | 无地址、流控制 |
| AHB | ARM | 中低速总线 | 单一突发、简单仲裁 |
| APB | ARM | 低速外设 | 简单读写 |
| PCIe | PCI-SIG | 高速串行互联 | TLP包、多通道 |
| USB | USB-IF | 通用串行总线 | 设备枚举、端点 |
| MIPI D-PHY | MIPI | 移动设备显示/相机 | 高速差分、低功耗 |
| SPI | 通用 | 低速串行外设 | 主从模式 |
| I2C | NXP | 两线制低速总线 | 多主仲裁 |

### 1.3 VIP集成方法

```systemverilog
// VIP集成示例
class my_env extends uvm_env;
    `uvm_component_utils(my_env)
    
    // VIP实例
    axi_vip::axi_master_agent  axi_mst_agent;
    axi_vip::axi_slave_agent   axi_slv_agent;
    axi_vip::axi_protocol_checker axi_checker;
    
    // 自定义组件
    my_scoreboard scoreboard;
    my_coverage      coverage;
    
    function void build_phase(uvm_phase phase);
        super.build_phase(phase);
        
        // 配置VIP
        uvm_config_db#(axi_vip::axi_agent_config)::set(this, "axi_mst_agent", 
            "config", axi_vip::axi_agent_config::type_id::create("mst_cfg"));
        
        // 创建VIP实例
        axi_mst_agent = axi_vip::axi_master_agent::type_id::create("axi_mst_agent", this);
        axi_slv_agent = axi_vip::axi_slave_agent::type_id::create("axi_slv_agent", this);
        axi_checker   = axi_vip::axi_protocol_checker::type_id::create("axi_checker", this);
        
        // 创建自定义组件
        scoreboard = my_scoreboard::type_id::create("scoreboard", this);
        coverage   = my_coverage::type_id::create("coverage", this);
    endfunction
    
    function void connect_phase(uvm_phase phase);
        // 连接VIP的分析端口到自定义组件
        axi_slv_agent.monitor.ap.connect(scoreboard.dut_export);
        axi_slv_agent.monitor.ap.connect(coverage.analysis_export);
        axi_mst_agent.monitor.ap.connect(axi_checker.analysis_export);
    endfunction
endclass
```

## 2. 回归测试管理

### 2.1 回归测试策略

回归测试是确保代码修改不引入新bug的系统性测试方法：

| 回归类型 | 说明 | 运行频率 | 用例数量 | 运行时间 |
|----------|------|----------|----------|----------|
| 冒烟测试（Smoke） | 基本功能快速验证 | 每次代码提交 | 10~50 | <30分钟 |
| 完整回归（Full） | 全量测试用例 | 每日/每周 | 1000~10000 | 数小时~数天 |
| 定向回归（Targeted） | 针对修改区域的测试 | 按需 | 50~500 | 1~4小时 |
| 覆盖率导向回归 | 针对覆盖率空洞 | 每周 | 500~2000 | 4~12小时 |

### 2.2 种子管理

随机仿真中，种子（seed）决定了随机数的生成序列。良好的种子管理是回归测试可复现性的关键：

$$\text{Test Result} = f(\text{seed}, \text{RTL version}, \text{testbench version})$$

```systemverilog
// 种子管理
class test_base extends uvm_test;
    // 通过命令行传递种子
    // vsim +UVM_TESTNAME=my_test +ntb_random_seed=12345
    
    function void build_phase(uvm_phase phase);
        super.build_phase(phase);
        
        // 记录种子信息
        int seed;
        seed = $urandom;  // 获取当前种子
        `uvm_info("SEED", $sformatf("Test seed: %0d", seed), UVM_LOW)
    endfunction
endclass
```

**种子管理最佳实践**：

- 每个测试用例的结果日志中记录使用的种子
- 发现bug时保存种子，确保可复现
- 建立种子数据库，记录每个种子的测试结果
- 使用不同种子运行同一测试用例多次（multi-seed run）

### 2.4 CI/CD集成

```bash
#!/bin/bash
# 回归测试CI/CD脚本示例

REGRESSION_LIST="smoke_tests.list"
SEED_COUNT=5
MAX_PARALLEL=16

# 并行运行仿真
run_regression() {
    local test_name=$1
    for ((seed=1; seed<=SEED_COUNT; seed++)); do
        random_seed=$RANDOM
        mkdir -p results/${test_name}_seed${seed}
        
        vcs -sverilog -ntb_opts uvm-1.2 \
            +UVM_TESTNAME=${test_name} \
            +ntb_random_seed=${random_seed} \
            -l results/${test_name}_seed${seed}/sim.log \
            &
        
        # 控制并行度
        if (( $(jobs -r | wc -l) >= MAX_PARALLEL )); then
            wait -n
        fi
    done
}

# 读取测试列表并运行
while read -r test; do
    run_regression "$test"
done < "$REGRESSION_LIST"

wait

# 收集结果
echo "========== Regression Summary =========="
pass=0; fail=0; error=0
for dir in results/*/; do
    if grep -q "TEST PASSED" ${dir}sim.log; then
        ((pass++))
    elif grep -q "UVM_FATAL\|UVM_ERROR" ${dir}sim.log; then
        ((fail++))
    else
        ((error++))
    fi
done
echo "PASS: ${pass}, FAIL: ${fail}, ERROR: ${error}"
echo "Pass Rate: $(echo "scale=2; ${pass}*100/(${pass}+${fail}+${error})" | bc)%"
```

## 3. 低功耗验证

### 3.1 UPF/CPF简介

随着移动设备和IoT芯片对功耗的严格要求，低功耗设计已成为主流。低功耗验证需要验证电源管理逻辑的正确性。

**UPF（Universal Power Format）**：

UPF是IEEE 1801标准，用于描述设计的功耗意图：

```
# UPF电源域定义示例
create_power_domain PD_CORE -include_scope
create_power_domain PD_ALWAYS -elements {always_on_inst}

create_supply_set VDD_CORE -function power
create_supply_set VSS -function ground

create_supply_net VDD_CORE -domain PD_CORE
create_supply_net VDD_ALWAYS -domain PD_ALWAYS

# 电源开关
create_power_switch SW_CORE \
    -domain PD_CORE \
    -input_supply_set {vin VDD_CORE} \
    -output_supply_set {vout VDD_SW} \
    -control_supply_set {ctrl pwr_ctrl}
```

**CPF（Common Power Format）**：

CPF是Cadence推出的功耗意图描述格式，功能与UPF类似但语法不同。

| 对比维度 | UPF | CPF |
|----------|-----|-----|
| 标准化 | IEEE 1801 | Cadence专有 |
| 支持工具 | 多厂商 | 主要Cadence |
| 语法风格 | Tcl-like | 专用语法 |
| 适用场景 | 通用 | Cadence流程 |

### 3.2 电源域验证

电源域验证需要检查以下关键场景：

```systemverilog
// 电源域切换序列验证
class power_domain_sequence extends uvm_sequence #(reg_transaction);
    `uvm_object_utils(power_domain_sequence)
    
    typedef enum {PD_ACTIVE, PD_SLEEP, PD_RETENTION, PD_SHUTDOWN} pd_state_e;
    
    task body();
        // 场景1：正常进入睡眠模式
        enter_sleep_mode();
        
        // 场景2：从睡眠模式唤醒
        exit_sleep_mode();
        
        // 场景3：保持寄存器在掉电时保持数据
        test_retention_registers();
        
        // 场景4：电源域隔离验证
        test_isolation_cells();
        
        // 场景5：电源时序验证
        test_power_sequencing();
    endtask
    
    task enter_sleep_mode();
        // 1. 设置隔离使能
        write_reg(ISOLATION_CTRL, 0x1);
        // 2. 保存关键状态到保持寄存器
        write_reg(RETENTION_CTRL, 0x1);
        // 3. 关闭电源开关
        write_reg(PWR_SWITCH_CTRL, 0x0);
        // 4. 验证电源域状态
        check_pd_state(PD_SLEEP);
    endtask
    
    task test_isolation_cells();
        // 验证隔离单元在电源域关闭时输出确定值
        write_reg(ISOLATION_CTRL, 0x1);
        write_reg(PD_CORE_PWR, 0x0);  // 关闭核心电源域
        
        // 检查隔离输出是否为钳位值
        check_isolation_output("iso_cell_0", 1'b0);  // 钳位到0
        check_isolation_output("iso_cell_1", 1'b1);  // 钳位到1
    endtask
endclass
```

### 3.3 隔离策略验证

隔离单元确保在不同电源域之间提供确定性的信号值：

| 隔离类型 | 钳位值 | 适用场景 |
|----------|--------|----------|
| 低电平钳位 | 输出固定为0 | 使能信号、复位信号 |
| 高电平钳位 | 输出固定为1 | 片选信号 |
| 保持最后值 | 输出保持关断前的值 | 数据信号 |
| 安全状态 | 输出进入预定义安全值 | 控制信号 |

### 3.4 保持寄存器验证

保持寄存器（Retention Register）在电源域关闭时保持数据不丢失：

```systemverilog
// 保持寄存器验证序列
task test_retention_reg();
    uvm_reg_data_t saved_value;
    uvm_status_e   status;
    
    // 1. 写入测试数据
    reg_model.retention_reg.write(status, 32'hDEAD_BEEF);
    
    // 2. 读取验证写入正确
    reg_model.retention_reg.read(status, saved_value);
    assert(saved_value == 32'hDEAD_BEEF) 
        else `uvm_error("RETENTION", "Write failed before power down")
    
    // 3. 进入保持模式（保存数据，关闭主电源）
    write_reg(PWR_CTRL, 0x2);  // retention mode
    #1000;
    
    // 4. 退出保持模式（恢复主电源）
    write_reg(PWR_CTRL, 0x1);  // active mode
    #1000;
    
    // 5. 读取验证数据保持正确
    reg_model.retention_reg.read(status, saved_value);
    assert(saved_value == 32'hDEAD_BEEF) 
        else `uvm_error("RETENTION", $sformatf(
            "Data lost! Expected 0xDEADBEEF, got 0x%08h", saved_value))
endtask
```
