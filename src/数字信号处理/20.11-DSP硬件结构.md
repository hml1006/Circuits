# 20.11 DSP硬件结构

> **前置知识**：[19.1 超标量CPU微架构](../CPU设计/19.1-超标量CPU微架构基础.md)（流水线与存储层次）、[6.5 RTL设计](../芯片设计/6.5-RTL设计.md)（RTL 描述与综合）、20.6 FIR滤波器设计。本章介绍数字信号处理器的硬件组织，以及对比普通 CPU 与 FPGA 实现的并行加速途径。

## 1. DSP 处理器与 MAC 单元

### 1.1 为什么需要专门的 DSP

DSP 运算以**乘累加（MAC）**、循环、流式存储访问为特征。例如 FIR 滤波器

$$
y[n] = \sum_{k=0}^{M-1} h[k]\, x[n-k]
$$

表面只是"乘加循环"，但通用 CPU 的寄存器结构、分支预测与数据预取并不完全匹配这种连续乘加的流式负载：循环开销大、双操作数访存慢、位反转无序访问低效。专用 **DSP 处理器**针对这些负载做了架构级优化，在单周期内完成一次 **MAC = 乘法 + 加法**，并内置循环寻址与地址自动增减。

### 1.2 MAC 单元结构

典型 MAC 单元由乘法器、累加器与保护位组成：

$$
\text{ACC} \mathrel{+}= A \times B
$$

工程要点：

- 采用**宽累加器**（如 32 位乘法 + 40 位累加），显著减少中间溢出（与 [20.10 §5 溢出处理](20.10-定点实现与量化误差.md) 呼应）
- 单周期、流水化，并提供可选的饱和输出
- 多次累加不落盘到普通寄存器，减少访存与寄存器压力
- 多数现代 DSP 同时配置 2~4 个 MAC 单元以支持并行

### 1.3 指令系统的 DSP 特色

DSP 指令集围绕"乘加流"设计，常见特色指令：

| 指令/特性 | 用途 |
|---------|-----|
| MAC/MACD（乘累加，可选双操作数） | FIR、IIR 滤波核心 |
| 乘 + 饱和累加 | 定点控制、防溢出 |
| 单周期双访存（双操作数加载） | 同时取系数与数据 |
| 循环缓冲（circular buffer）指令 | 滑窗滤波 |
| 位反转寻址 | FFT 重排 |
| 零开销循环指令（RPT/REP） | 减少循环分支开销 |
| 归一化/块浮点指令 | 宽动态范围缩放 |

这些指令把"滤波器、FFT、定点控制"等高频负载编译成紧凑的流水序列，是用一条指令完成过去多条指令工作的架构级体现。

### 1.4 存储层次与 DMA

DSP 系统围绕**片上存储**与 **DMA 传输**组织数据流：

- **指令缓存 + 数据存储器**：哈佛架构把指令与数据分开，减少取指/取数冲突
- **片上 SRAM 与多组存储体**：支持并发读取多个操作数，供双 MAC 并行取数
- **DMA 控制器**：在与运算单元并行地把外设/ADC 数据搬入内存，或把结果搬出，避免 CPU 花指令等待；一次"采集-处理-输出"在 DMA 与运算流水并行下形成真正的数据流
- **外设接口**：串口、并口、ADC/DAC 接口、音频总线（I²S）等，配合中断让 DSP 高效响应实时事件

工程上常按"采样中断 → DMA 搬运 → DSP 计算 → 输出"的流水来组织实时链路，把处理延迟压到最小。

## 2. 流水线

DSP 处理器采用深度流水线，把指令执行分解为若干阶段：

1. **IF** 取指：从指令存储器取指令
2. **ID** 译码：解析操作码与操作数来源
3. **R** 读取：读寄存器/数据存储器（双操作数）
4. **X/MAC** 执行：完成乘累加等运算
5. **W** 写回：写回累加器或寄存器

流水线保证每时钟周期完成一条（或更多）指令。与通用 CPU（[19.1 超标量CPU微架构](../CPU设计/19.1-超标量CPU微架构基础.md)）不同，DSP 通过**零开销循环、无分支 GOTO**与并行数据通道来减少流水线停顿。流水线化要求正确处理**数据冒险**（如写后读），RTL 中需仔细规划时序与旁路（forwarding）。

**零开销循环**是 DSP 流水线的关键特性：硬件循环计数器在后台自动减小，循环体末尾不再需要显式的跳转与比较指令，从而避免每次循环迭代的流水线冲刷开销。配合流水化的 MAC，一个 $M$ 阶 FIR 每次采样只需 $M$ 个时钟周期即可完成，吞吐得到数量级提升。

### 2.1 流水线冒险与处理

- **结构冒险**：哈佛架构分离指令/数据存储器，减少访存冲突
- **数据冒险**：写后读依赖通过**旁路（forwarding）**与延迟槽化解
- **控制冒险**：由零开销循环、延迟跳转指令规避大部分跳转开销

## 3. 循环寻址与数据通路

### 3.1 循环寻址（Modulo Addressing）

滤波器与 FFT 需要环形缓冲区存放滑窗数据。DSP 提供**循环寻址**：地址递增到达缓冲区边界时自动回绕到起点，免去软件取模开销。长度须为 2 的幂以简化回绕逻辑，配合延迟链即可高效实现 FIR 卷积——每次迭代自动覆盖最旧样本并接入最新样本。

### 3.2 并行数据通路

嵌入式 DSP 常采用**哈佛架构**（指令、数据总线分离）、双操作数总线（两个独立数据总线，可将系数与数据同时取入两组寄存器）与多组寄存器，允许单条指令同时读两个操作数、单周期执行双访存，进一步提高吞吐。

### 3.3 SIMD 与 VLIW

- **SIMD（单指令多数据）**：一条指令对多个连续地址数据并行执行同样运算，对批量乘累加与向量 FFT 有良好加速比
- **VLIW（超长指令字）**：一条宽指令同时编码多个互不依赖的操作，由编译器静态调度并行，规避硬件动态调度复杂度——典型如 TI C6x、CEVA 等架构

## 4. FFT 与 DSP 的硬件加速

FFT 要求按蝶形图（[20.5 §2 快速傅里叶变换](20.5-快速傅里叶变换.md)）访问数据，处理器的**位反转寻址**（bit-reversal）与循环寻址为 FFT 提供高效支撑：

- **位反转寻址**：地址线交叉映射（位序颠倒），使蝶形运算两输入的位置能按位反转规律一次取齐，省去数据重排的额外循环
- **旋转因子 LUT**：各级 $W_N^k$ 预存于查找表，避免实时计算三角函数
- **SIMD 蝶形**：一条指令同时执行多个蝶形的加减，配合双 MAC 提高各阶段吞吐
- DSP 的宽累加器与饱和也直接服务于 FFT 定点实现中的数值控制（见 [20.10](20.10-定点实现与量化误差.md)）

## 5. FPGA 并行实现

FPGA 用大规模并行乘法器、DSP 块（如 Xilinx DSP48、Intel DSP block）、片上存储器与可编程逻辑，把算法映射为**数据流硬件**：

- 各级 FIR 可并行展开成**转置结构**（数据广播、各乘法器并行、结果沿加法链前移），实现单周期输出（见 [20.6 §5 实现结构](20.6-FIR滤波器设计.md)）
- FFT 核采用**流水蝶形处理单元**与多级乒乓缓冲，吞吐可达每秒数百 MMAC，远高于通用处理器
- 以 RTL（[6.5 RTL设计](../芯片设计/6.5-RTL设计.md)）描述算法，经综合、布局布线生成硬件；流水线与并行度是决定吞吐的关键参数
- 相比处理器，FPGA 的能耗比与延迟可大幅改善，但开发周期与时钟频率成本更高

## 6. 三种实现途径的权衡

| 特性 | 通用 CPU / MCU | DSP / ASIC | FPGA |
|-----|--------------|-----------|------|
| 灵活性 | 高（软件） | 中（指令集 / 硬连线） | 中高（可重配置） |
| 性能/吞吐 | 低 | 高 | 很高（并行） |
| 功耗 | 中 | 低 | 中高 |
| 开发周期 | 快 | 最慢（ASIC） | 中 |
| 适用场景 | 控制、普适 | 高吞吐、低功耗流处理 | 高并行、可重配置流处理 |

**设计选择**需要在开发速度、性能、功耗与灵活性之间权衡：原型与复杂控制用处理器，大批量高吞吐用 DSP/ASIC，高度并行的流处理用 FPGA。

## 7. 工程 / 典型应用

- **移动通信基带**：OFDM 调制（IFFT/FFT）、信道均衡与 Turbo/LDPC 编解码
- **音频/视频编解码器**（AAC、H.264/HEVC）：滤波器组、DCT 与运动估计
- **雷达信号处理**：脉冲压缩、多普勒 FFT、自适应波束成形——多依赖并行 DSP 阵列或 FPGA
- **电机控制与电源**：低功耗定点 DSP 实现 FOC 磁场定向控制与数字环路补偿
- **车规 / 无人机传感器融合**：嵌入式 DSP 运行降噪、滤波与谱估计实时处理算法

## 小结

- DSP 处理器围绕 MAC、循环、流式访存做架构级优化，哈佛结构与双总线支撑高吞吐
- 宽累加器、饱和输出、循环寻址、位反转在硬件层面支持滤波器与 FFT
- 流水线、SIMD、VLIW 三种并行手段提升单芯片吞吐
- FPGA 用并行 DSP 块与数据流硬件实现高吞吐、可重配置的流处理
- 处理器 / DSP/ASIC / FPGA 三者在灵活性、性能、功耗、周期上各有取舍，按应用选择
