# 6.6 嵌入式系统、操作系统与编译基础

> **本章定位**：补上“芯片如何跑起软件”的一层：启动流程、交叉编译、中断、RTOS、内存管理与驱动模型。

> **前置知识**：**必需** [3.11 从逻辑门到单周期处理器](../../03-数字与计算机系统/计算机组成原理/3.11-从逻辑门到单周期处理器.md)–[3.16 虚拟内存与存储管理](../../03-数字与计算机系统/CPU设计/3.16-虚拟内存与存储管理.md)（处理器、存储层次与虚拟内存）。

## 1. 嵌入式系统组成

典型嵌入式系统：

```
MCU/SoC + 电源 + 时钟 + 复位 + 存储 + 外设 + 软件
```

软件分层：

| 层 | 内容 |
|---|---|
| 硬件 | CPU、存储器、外设、总线 |
| 启动代码 | Boot ROM、Bootloader |
| 内核 | RTOS/Linux、任务调度、内存管理 |
| 驱动 | UART、SPI、I2C、GPIO、ADC、DMA |
| 应用 | 控制算法、通信协议、UI |

与通用计算机相比，嵌入式系统强调**实时性、低功耗、成本、可靠性**。

## 2. 启动流程与链接脚本

### 2.1 上电到 main

典型流程：

1. 上电复位，CPU 从固定地址取指；
2. Boot ROM 初始化时钟、判断启动介质；
3. Bootloader 加载应用镜像；
4. 初始化栈、堆、`.data`、`.bss`；
5. 调用 `main()`。

### 2.2 链接脚本

链接脚本决定代码/数据放在哪段地址：

```ld
MEMORY {
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
  RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}
SECTIONS {
  .text : { *(.text*) } > FLASH
  .data : { *(.data*) } > RAM AT > FLASH
  .bss  : { *(.bss*)  } > RAM
}
```

`.data` 初值存在 Flash，启动时拷贝到 RAM；`.bss` 清零。栈、堆大小要按最坏调用深度与动态分配估算。

### 2.3 向量表

中断向量表放在 Flash 起始或 RAM 中，包含复位、NMI、HardFault、外设中断入口。Bootloader 跳转应用时要重定位向量表（如 Cortex-M 的 `VTOR`）。

## 3. 交叉编译与构建

### 3.1 工具链

- `arm-none-eabi-gcc`：裸机/RTOS；
- `aarch64-linux-gnu-gcc`：Linux 应用；
- `clang`/`llvm`：可选。

### 3.2 编译流程

```
预处理 → 编译 → 汇编 → 链接 → 二进制/HEX
```

常用命令：

```bash
arm-none-eabi-gcc -mcpu=cortex-m4 -O2 -c main.c -o main.o
arm-none-eabi-gcc -T linker.ld main.o startup.o -o firmware.elf
arm-none-eabi-objcopy -O binary firmware.elf firmware.bin
```

### 3.3 优化与调试

- `-O0` 便于调试，`-O2/-Os` 用于发布；
- `volatile` 防止编译器优化掉寄存器访问；
- `__attribute__((section))` 放置特殊段；
- 用 `objdump`、`nm`、`size` 检查代码/数据大小。

## 4. 中断、异常与时钟

### 4.1 中断流程

1. 外设置中断标志；
2. NVIC/中断控制器判优先级；
3. CPU 保存现场，跳转 ISR；
4. ISR 清标志、处理数据；
5. 返回，恢复现场。

### 4.2 实时性

中断延迟 = 硬件响应 + 保存现场 + 跳转；中断嵌套与优先级抢占影响最坏延迟。长 ISR 应拆分到任务中，避免阻塞高优先级中断。

### 4.3 时钟与定时器

- 系统时钟树：外部晶振 → PLL → 总线/外设时钟；
- 定时器：PWM、输入捕获、定时中断；
- 看门狗：防止程序跑飞。

## 5. RTOS 调度与同步

### 5.1 任务与调度

RTOS 任务有优先级、栈、状态（就绪/运行/阻塞）。调度策略：

- 抢占式优先级调度：高优先级就绪立即抢占；
- 时间片轮转：同优先级公平；
- 合作式调度：任务主动让出。

### 5.2 同步与通信

- 信号量：资源计数/同步；
- 互斥量：保护共享资源，注意优先级反转；
- 消息队列：任务间传数据；
- 事件标志：多事件等待。

### 5.3 优先级反转

低优先级任务持有互斥量，高优先级任务等待，中优先级任务抢占，导致高优先级被长时间阻塞。解决办法：优先级继承、优先级天花板。

## 6. 内存管理与驱动

### 6.1 裸机内存布局

```
Flash: .text .rodata .data初值
RAM:   .data .bss heap → stack
```

栈向下/向上增长由架构决定；堆与栈相向增长时要留足余量。

### 6.2 MMU/MPU

- MMU：虚拟内存、页表、权限；
- MPU：区域保护，适合 MCU；
- 无保护：任何指针错误都可能改坏系统。

### 6.3 驱动模型

驱动通常分：

- 寄存器操作层（读写寄存器）；
- 设备抽象层（初始化、读、写、ioctl）；
- 总线匹配层（设备树/ID 表）。

Linux 驱动用 `file_operations`、`probe/remove`、设备树；RTOS 驱动常用统一的 `open/read/write/ioctl` 接口。

## 小结

- 嵌入式系统由硬件、启动代码、内核、驱动、应用组成；实时性、低功耗、成本、可靠性是核心约束。
- 启动流程与链接脚本决定代码/数据布局；向量表与 Bootloader 跳转是关键细节。
- 交叉编译、`volatile`、段属性、`size`/`objdump` 是日常工具。
- 中断延迟、RTOS 调度、优先级反转直接影响实时性。
- MMU/MPU 与驱动模型把硬件抽象给应用；理解寄存器与总线是调试的基础。
