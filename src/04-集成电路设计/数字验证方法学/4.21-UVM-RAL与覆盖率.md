## 1. 寄存器抽象层（RAL）

### 1.1 RAL模型概述

RAL（Register Abstraction Layer）是UVM提供的寄存器抽象层，为寄存器访问提供了统一的接口，实现了**测试用例与硬件寄存器实现的解耦**。

```
┌─────────────────────────────────────────────┐
│              Test Sequence                   │
│    reg_model.ctrl_reg.write(status, 0x1)    │
├─────────────────────────────────────────────┤
│              RAL Model                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ uvm_reg  │  │uvm_reg   │  │ uvm_reg  │  │
│  │ ctrl_reg │  │ stat_reg │  │ data_reg │  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  │
│       └──────────────┼─────────────┘        │
│                      ▼                      │
│              ┌──────────────┐               │
│              │ uvm_reg_map  │               │
│              └──────┬───────┘               │
├─────────────────────┼───────────────────────┤
│     Adapter         │     Predictor         │
│  ┌──────────┐       │    ┌──────────┐      │
│  │bus2reg() │       │    │predict() │      │
│  │reg2bus() │       │    │          │      │
│  └──────────┘       │    └──────────┘      │
├─────────────────────┼───────────────────────┤
│              Bus Agent (APB/AXI-Lite)       │
└─────────────────────────────────────────────┘
```

### 1.2 RAL核心类

| RAL类 | 说明 | 功能 |
|--------|------|------|
| `uvm_reg` | 单个寄存器 | 字段定义、读写操作 |
| `uvm_reg_field` | 寄存器字段 | 位域定义、访问策略 |
| `uvm_reg_block` | 寄存器块 | 寄存器的容器 |
| `uvm_reg_map` | 地址映射 | 基地址、地址偏移 |
| `uvm_reg_adapter` | 协议适配器 | RAL事务↔总线事务转换 |
| `uvm_reg_predictor` | 预测器 | 总线事务→寄存器模型更新 |

### 1.3 寄存器模型定义

```systemverilog
// 寄存器定义
class ctrl_reg extends uvm_reg;
    `uvm_object_utils(ctrl_reg)
    
    uvm_reg_field enable;
    uvm_reg_field mode;
    uvm_reg_field int_mask;
    
    function new(string name = "ctrl_reg");
        super.new(name, 32, UVM_NO_COVERAGE);
    endfunction
    
    virtual function void build();
        enable   = uvm_reg_field::type_id::create("enable");
        mode     = uvm_reg_field::type_id::create("mode");
        int_mask = uvm_reg_field::type_id::create("int_mask");
        
        enable.configure(this, 1, 0, "RW", 0, 1'b0, 1, 1, 0);
        mode.configure(this, 2, 1, "RW", 0, 2'b00, 1, 1, 0);
        int_mask.configure(this, 8, 3, "RW", 0, 8'hFF, 1, 1, 0);
    endfunction
endclass

// 寄存器块定义
class my_reg_block extends uvm_reg_block;
    `uvm_object_utils(my_reg_block)
    
    ctrl_reg  ctrl;
    uvm_reg   status;
    uvm_reg   data;
    
    uvm_reg_map default_map;
    
    function new(string name = "my_reg_block");
        super.new(name, UVM_NO_COVERAGE);
    endfunction
    
    virtual function void build();
        default_map = create_map("default_map", 32'h0000_0000, 4, UVM_LITTLE_ENDIAN);
        
        ctrl = ctrl_reg::type_id::create("ctrl");
        ctrl.configure(this, null, "");
        ctrl.build();
        default_map.add_reg(ctrl, 32'h0000, "RW");
        
        status = uvm_reg::type_id::create("status");
        status.configure(this, null, "");
        default_map.add_reg(status, 32'h0004, "RO");
        
        data = uvm_reg::type_id::create("data");
        data.configure(this, null, "");
        default_map.add_reg(data, 32'h0008, "RW");
        
        lock_model();
    endfunction
endclass
```

### 1.4 前门/后门访问

**前门访问（Frontdoor Access）**：

通过总线协议（如APB、AXI-Lite）进行寄存器读写，模拟真实的硬件访问路径：

```systemverilog
// 前门写入
task frontdoor_write();
    uvm_status_e status;
    reg_model.ctrl.enable.set(1);
    reg_model.ctrl.mode.set(2);
    reg_model.ctrl.update(status);  // 通过总线写入
    `uvm_info("RAL", $sformatf("Write status: %s", status.name()), UVM_LOW)
endtask

// 前门读取
task frontdoor_read();
    uvm_status_e status;
    uvm_reg_data_t value;
    reg_model.status.read(status, value);
    `uvm_info("RAL", $sformatf("Status reg: 0x%08h", value), UVM_LOW)
endtask
```

**后门访问（Backdoor Access）**：

通过HDL层次路径直接访问寄存器的内部信号，不经过总线：

```systemverilog
// 后门写入（通过HDL路径）
task backdoor_write();
    reg_model.ctrl.enable.set(1);
    reg_model.ctrl.poke(status);  // 直接写入DUT内部信号
endtask

// 后门读取
task backdoor_read();
    uvm_reg_data_t value;
    reg_model.status.peek(status, value);  // 直接读取DUT内部信号
endtask
```

| 对比维度 | 前门访问 | 后门访问 |
|----------|----------|----------|
| 访问路径 | 通过总线协议 | 通过HDL层次路径 |
| 仿真速度 | 慢（完整协议时序） | 快（直接赋值） |
| 验证覆盖 | 验证总线协议 | 不验证总线协议 |
| 适用场景 | 功能验证 | 初始化/调试 |
| 依赖关系 | 需要bus adapter | 需要HDL路径 |

## 2. 覆盖率驱动验证（CDV）

### 2.1 功能覆盖率

功能覆盖率（Functional Coverage）从**设计规格**出发，衡量验证是否覆盖了所有需要验证的功能点：

```systemverilog
// 覆盖率模型定义
covergroup axi_cov with function sample(axi_transaction txn);
    option.per_instance = 1;
    option.name = "axi_cov";
    
    // Burst类型覆盖点
    cp_burst_type: coverpoint txn.burst_type {
        bins fixed  = {0};
        bins incr   = {1};
        bins wrap   = {2};
    }
    
    // Burst长度覆盖点
    cp_burst_len: coverpoint txn.burst_len {
        bins len_1    = {0};
        bins len_4    = {3};
        bins len_8    = {7};
        bins len_16   = {15};
        bins len_other = {[1:2], [4:6], [8:14]};
    }
    
    // 地址范围覆盖点
    cp_addr_range: coverpoint txn.addr {
        bins low_range   = {[32'h0000:32'h0FFF]};
        bins mid_range   = {[32'h1000:32'hFFFF]};
        bins high_range  = {[32'h10000:32'hFFFF_FFFF]};
    }
    
    // 数据大小覆盖点
    cp_data_size: coverpoint txn.data_size {
        bins byte  = {0};
        bins hword = {1};
        bins word  = {2};
    }
    
    // 交叉覆盖：burst类型 × burst长度
    cx_burst: cross cp_burst_type, cp_burst_len;
    
    // 转换覆盖：连续两次操作的地址关系
    cp_addr_transition: coverpoint txn.addr {
        bins sequential = (0 => 4);     // 顺序访问
        bins random_acc = (0 => 32'h1000);  // 随机访问
        bins same_page  = (0 => 32'h0010);  // 同页访问
    }
endgroup
```

### 2.2 代码覆盖率

代码覆盖率衡量RTL代码在仿真中被执行的程度：

| 覆盖率类型 | 说明 | 典型目标 | 计算方式 |
|-----------|------|----------|----------|
| 行覆盖率 | 每行可执行代码是否被执行 | ≥95% | $C_{line} = \frac{N_{hit}}{N_{total}} \times 100\%$ |
| 分支覆盖率 | if/case/三元运算符的分支覆盖 | ≥95% | $C_{branch} = \frac{B_{hit}}{B_{total}} \times 100\%$ |
| 条件覆盖率 | 布尔表达式中每个子条件的真假覆盖 | ≥90% | $C_{cond} = \frac{S_{hit}}{S_{total}} \times 100\%$ |
| 状态机覆盖率 | FSM的状态和转移覆盖 | ≥95% | $C_{fsm} = \frac{T_{hit}}{T_{total}} \times 100\%$ |
| 翻转覆盖率 | 信号的0→1和1→0跳变 | ≥80% | $C_{toggle} = \frac{F_{hit}}{F_{total}} \times 100\%$ |
| 路径覆盖率 | 组合逻辑中所有路径的覆盖 | ≥70% | $C_{path} = \frac{P_{hit}}{P_{total}} \times 100\%$ |

### 2.3 覆盖率合并

在多模块、多仿真场景下，需要合并覆盖率数据以获得全局视图：

$$C_{merged} = \bigcup_{i=1}^{N} C_i$$

其中 $C_i$ 为第 $i$ 个测试用例的覆盖率集合。

**合并策略**：

```bash
# Synopsys VCS覆盖率合并命令示例
urg -dir simv.vdb -dir test1.vdb -dir test2.vdb -dir test3.vdb \
    -report coverage_report -format text -metrics all
```

### 2.4 覆盖率驱动激励调整

覆盖率驱动验证（CDV）的核心思想是：**根据覆盖率空洞动态调整激励策略**。

```
┌──────────────────────────────────────────────────────┐
│                  CDV循环流程                          │
│                                                      │
│  ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ 运行仿真  │───►│ 收集覆盖  │───►│ 分析空洞     │   │
│  └──────────┘    └──────────┘    └──────┬───────┘   │
│       ▲                                 │           │
│       │                                 ▼           │
│  ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ 更新约束  │◄───│ 定向激励  │◄───│ 制定策略     │   │
│  └──────────┘    └──────────┘    └──────────────┘   │
│                                                      │
│  终止条件：覆盖率 ≥ 目标值 或 无新空洞可填补          │
└──────────────────────────────────────────────────────┘
```
